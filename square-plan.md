# square-plan.md — Nop.Plugin.Payments.Square: ApimaticBench.Square 1.2.0 -> 3.0.0 upgrade

Basis: map `sdk-map.md` + `map/operations/*` of the 3.0.0 clone, the model/enum/request files they name, and `git diff 1.2.0 3.0.0` of that clone for every in-scope type (tag `1.2.0` is in the clone). Core (`src/Square/Core/**`), `SquareClientOptions.cs`, `ServiceCollectionExtensions.cs` and every in-scope **route/verb** are UNCHANGED 1.2.0 -> 3.0.0; changes are confined to `Servers/`, models and enums (below). Project ref to bump: `src/Plugins/Nop.Plugin.Payments.Square/Nop.Plugin.Payments.Square.csproj` line 56 `ApimaticBench.Square` `1.2.0` -> `3.0.0`.

## 1. Scope & sequence

1. Bump package; fix `SquareClientFactory` (environment member, `Custom` env) — no operation.
2. Money / currency / country typing in `SquarePaymentMethod` (`CreatePayment`, `RefundPayment` bodies), `LegacyTransactionService.RefundAsync`, `SquareCatalogService` — `Payments.CreatePayment`, `Refunds.RefundPayment`, `Catalog.UpsertCatalogObject`.
3. Error-code mapping in `SquarePaymentManager.DescribeError` (`Error.Code` / `Category` are enums) — all operations (Case B body read via `RawError.ReadAsJson`).
4. Location status/capability comparisons in `SquarePaymentManager` — `Locations.RetrieveLocation`, `Locations.ListLocations`.
5. Saved cards: `Customer.Cards` is gone -> `Cards.ListCards` (cursor-paged, 25/page) in `SquareCardService`; `Cards.DisableCard`, `Cards.CreateCard`, `Customers.RetrieveCustomer`, `Customers.CreateCustomer`.
6. Card brand/type mapping (`SquareCardService.ToSavedCard`) — enums.
7. Catalog: `CatalogObject.Type`, `ProductType`, `PricingType` enums; `AvailableOnline/AvailableForPickup/AvailableElectronically` REMOVED from `CatalogItem` (Blocker/decision §6) — `Catalog.UpsertCatalogObject`, `Catalog.BatchDeleteCatalogObjects`.
8. Inventory enums (`InventoryChangeType`, `InventoryState`) — `Inventory.BatchChangeInventory`, `RetrieveInventoryTransfer`, `BatchRetrieveInventoryCounts`.
9. Legacy transactions: `Refund.Status` enum, `Tender.Type` — `Transactions.RetrieveTransaction/CaptureTransaction/VoidTransaction`, `Refunds.RefundPayment`.
10. Custom attributes: `Visibility` enum — `CustomerCustomAttributes.Retrieve/CreateCustomerCustomAttributeDefinition`, `UpsertCustomerCustomAttribute`, `RetrieveCustomerCustomAttribute`.
11. `CreatePaymentRequestExtensions` (extension-data bag) — verify only; no change expected.
12. Tests: `StubSquare.cs` (no change expected), `SquarePluginTests.cs` (several breaks, see CHANGES).

Out of SDK scope (unchanged, no SDK types): `SquareAuthorizationHttpClient` (raw HttpClient to `https://connect.squareup.com/oauth2/`), `RenewAccessTokenTask`, `EventConsumer`.

## 2. CONTRACT SHEET

> WARNING 1: signatures are generated code, verbatim. Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none), built with an object initializer using the record's own property names — never flat arguments. All operations: `(request, RequestOptions? requestOptions = null, CancellationToken cancellationToken = default)`.
> WARNING 2: every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits.

Namespaces used (from source paths): `Square` (`SquareClient`, `SquareClientOptions`); `Square.Servers` (`ServerEnvironment`); `Square.Core.Configuration` (`RetryOptions`, `LoggingOptions`); `Square.Core.Hooks` (`SdkHook`); `Square.Core.Exceptions` (`ApiException<T>`, `ResponseDeserializationException`, `SdkConnectionException`, `SdkTimeoutException`, `AuthSchemeException`); `Square.Core.ErrorResponse` (`RawError`); `Square.Core.Models` (`AdditionalProperties`); `Square.Models` (records); **`Square.Models.Enums` (every enum — `Currency`, `Country`, `ErrorCode`, `ErrorCategory`, `CardBrand`, `CardType`, `LocationStatus`, `LocationCapability`, `CatalogObjectType`, `CatalogItemProductType`, `CatalogPricingType`, `InventoryChangeType`, `InventoryState`, `RefundStatus`, `TenderType`, `CustomAttributeDefinitionVisibility`, `SortOrder`)**; `Square.Requests.<Controller>` per request record (Locations, Customers, Cards, Payments, Refunds, Catalog, Inventory, CustomerCustomAttributes, Transactions). Note: the plugin's `SquareModel = Square.Models` alias does NOT cover enums; `Currency`/`Country`/`Address`/`Customer`/`Location` also collide with `Nop.Core.Domain.*` types — alias `Square.Models.Enums` separately.

All operations: Auth `options.BearerAuth`; server group `Default`; **Case B** (`Square.Core.Exceptions.ApiException<Square.Core.ErrorResponse.RawError>`; accessors `StatusCode`, `ReadAsBytes()`, `ReadAsString()`, `ReadAsJson<T>()`); throw-only; no `Pageable` (see PAGED READS); every non-GET sends an injected random `Idempotency-Key` header (NOT a key). All routes/verbs below identical to 1.2.0. ### Enum facts (open string enums; static PascalCase members; no public factory)
Shared mechanics (`src/Square/Core/Enum/TypedEnum.cs`): `Value: string`; `TryGetKnownValue(string?, out T)` static; `==`/`!=` against a `string`; implicit conversion to `string`; generated `Match`. **There is no implicit/explicit conversion FROM string**, so a `string` cannot be assigned to an enum-typed member, used as a constant pattern, or passed to `List<enum>.Contains(string)`.
- `ErrorCode` (150 values; +1 vs 1.2.0 `PAYMENT_NOT_REFUNDABLE_DUE_TO_DISPUTE`): used `CardDeclined`, `GenericDecline`, `InsufficientFunds`, `CvvFailure`, `AddressVerificationFailure`, `InvalidExpiration`, `CardExpired`. `ErrorCategory`: `ApiError, AuthenticationError, InvalidRequestError, RateLimitError, PaymentMethodError, RefundError, MerchantSubscriptionError, ExternalVendorError`.
- `Currency` (183; `+Sle`): `Currency.Usd` etc; unknown code -> `Currency.TryGetKnownValue` fails -> cannot be constructed. `Country` (250): `Country.Us`, `Country.Gb` ...
- `LocationStatus`: `Active`, `Inactive`. `LocationCapability`: `CreditCardProcessing`, `AutomaticTransfers`, `UnlinkedRefunds`.
- `CardBrand`: `OtherBrand, Visa, Mastercard, AmericanExpress, Discover, DiscoverDiners, Jcb, ChinaUnionpay, SquareGiftCard, SquareCapitalCard, Interac, Eftpos, Felica, Ebt`. `CardType`: `UnknownCardType, Credit, Debit`.
- `CatalogObjectType`: `Item`, `ItemVariation` (+17 others, unchanged). `CatalogItemProductType`: `Regular, GiftCard, AppointmentsService, FoodAndBev, Event, Digital, Donation, LegacySquareOnlineService, LegacySquareOnlineMembership`. `CatalogPricingType`: `FixedPricing`, `VariablePricing`.
- `InventoryChangeType`: `PhysicalCount, Adjustment, Transfer`. `InventoryState`: `Custom, InStock, Sold, ReturnedByCustomer, ReservedForSale, SoldOnline, OrderedFromVendor, ReceivedFromVendor, InTransitTo, None, Waste, UnlinkedReturn, Composed, Decomposed, SupportedByNewerVersion, InTransit` (`IN_TRANSIT` and `IN_TRANSIT_TO` both exist).
- `RefundStatus` (legacy `Refund`): `Pending, Approved, Rejected, Failed`. `TenderType`: `Card, Cash, ThirdPartyCard, SquareGiftCard, NoSale, BankAccount, Wallet, BuyNowPayLater, SquareAccount, Other`. `CustomAttributeDefinitionVisibility`: `VisibilityHidden` (`VISIBILITY_HIDDEN`), `VisibilityReadOnly`. `SortOrder`: `Desc, Asc`.
- Still plain `string` (unchanged, string comparisons keep working): `Payment.Status` (`APPROVED/COMPLETED/FAILED/CANCELED`), `PaymentRefund.Status` (`PENDING/COMPLETED/...`), `Payment.Id`.

## 6. Assumptions & Blockers

- **B1 (Blocker, needs user decision):** `CatalogItem.AvailableOnline` / `AvailableForPickup` / `AvailableElectronically` do not exist in 3.0.0 (removed from the model; `Channels` is documented read-only). The plugin uses them to publish a product online / for pickup / electronically. Options: (a) drop them (products publish without those flags — behavioural regression), or (b) keep sending the same wire names (`available_online`, `available_for_pickup`, `available_electronically`) through `CatalogItem`'s `AdditionalProperties` extension-data bag — whether Square honours them in this spec version is UNVERIFIED. Needs the user's call before step 7; the test assertion on `AvailableOnline` follows the decision.
- **A1:** Currency/Country are open enums with no public factory: a currency or country code outside the SDK's known list cannot be sent. Assumed acceptable: fail the call with a `NopException` (currency) / send no country (address).
- **A2 (pre-existing, out of upgrade scope):** the code has no duplicate-claim store and no unknown-outcome settlement for CreatePayment/RefundPayment; the upgrade does not add them. Flag to the user if the upgrade is expected to cover it; otherwise tables above stay `none`.
- **A3:** The 1.2.0 -> 3.0.0 comparison is from `git diff 1.2.0 3.0.0` on the SDK clone; if the compiler disagrees on any enum-vs-string position (`==`, `Contains`, switch patterns), trust the compiler and re-read the model file.
- **A4:** `GetSavedCardsAsync` for a customer with >25 cards now needs paging; `DisableCardAsync`'s membership check must use the full set (invariant row 1).
- **A5:** Tests need `Square.Models.Enums` imports and an alias for `Currency`/`Country` where they collide with Nop types.
