# Square plan — upgrade `ApimaticBench.Square` 1.2.0 → 3.0.0 (Nop.Plugin.Payments.Square)

Scope: every existing SDK use in `src/Plugins/Nop.Plugin.Payments.Square` and `src/Tests/Nop.Plugin.Payments.Square.Tests`, checked against the 3.0.0 map and source. No new features; where 3.0.0 removes something the code relied on, the replacement is named and marked. `SquareAuthorizationHttpClient` (OAuth obtain/renew/revoke) uses its own `HttpClient` and plugin `Domain/` types, not the SDK, so it is out of scope. No other project in the repo references the package.

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none), built with an object initializer whose property names are the record's own. Never pass flat arguments. Every method is `(Request request, RequestOptions? requestOptions = null, CancellationToken cancellationToken = default)` and returns `Task<Response>`.
> ⚠ **Every SDK type is written fully-qualified with the namespace its source path implies**, taken from the path the map gives for THAT type: records are `Square.Models.*` (`src/Square/Models/`), enums are `Square.Models.Enums.*` (`src/Square/Models/Enums/`), request records are `Square.Requests.<Controller>.*`, and `RawError` is `Square.Core.ErrorResponse`. Exceptions are `Square.Core.Exceptions`. Inside `namespace Nop.Plugin.Payments.Square…` a bare `Square.X` resolves to the plugin namespace, so qualify as `global::Square.X` or use a `using` alias (see T2).

Every operation below is **Case B**: `ApiException<Square.Core.ErrorResponse.RawError>` (`StatusCode`, `ReadAsBytes()`, `ReadAsString()`, `ReadAsJson<T>()`). Auth is `options.BearerAuth`, the server group is `Default`, and there is no SDK pagination unless a row says otherwise. Every response envelope also carries `Errors (errors): IReadOnlyList<Square.Models.Error>?`.

## 3. Trap notes

- **T1 (steps 3–10, enums):** every string field that became an enum is a sealed record, not a C# enum or a string. - **T2 (all steps):** the plugin's namespace is `Nop.Plugin.Payments.Square`, so a qualified name starting `Square.` resolves to the plugin, not the SDK. `SquarePaymentMethod` also imports nopCommerce `Currency`, `Address` and `Country` types that clash with the SDK enums of the same name. Getting either wrong costs CS0234 or CS0104, or the wrong type bound silently. **MUST load `bench-square:dotnet-getting-started`** (*Namespaces*)

## 6. Assumptions & Blockers

- **A1 (assumption):** 1.2.0's `ServerEnvironment.Environment2` was the sandbox host; the code selects it only when `UseSandbox` is set. 3.0.0's `ServerEnvironment.Sandbox` is `https://connect.squareupsandbox.com`. The 1.2.0 source was not available to confirm the old URL.
- **A2 (behaviour change: catalog availability):** 3.0.0's `CatalogItem` no longer declares `available_online`, `available_for_pickup` or `available_electronically`. Behaviour can be kept on the wire by writing those three keys into `CatalogItem.AdditionalProperties` (the same technique the plugin uses for `integration_id`). Whether Square still honours them is UNVERIFIED. The model dropping them suggests the API may ignore them. **Decided:** sent through `CatalogItem.AdditionalProperties` (`available_online`, `available_for_pickup`, `available_electronically`) in `SquareCatalogService.UpsertProductAsync`, so the wire request is unchanged; whether Square still honours them stays UNVERIFIED. The catalog test now reads `available_online` from the bag.
- **A3 (behaviour change: currency and country):** `Money.Currency` and `Address.Country` are now closed to the codes the SDK declares (no public factory). A store currency that passes `CheckSupportCurrency` but is not a declared `Currency` member cannot be sent. **Decided:** an undeclared currency fails with the existing "currency is not supported by the Square" `NopException` (`SquarePaymentMethod.GetSquareCurrency`, `LegacyTransactionService.RefundAsync`, `SquareCatalogService.UpsertProductAsync`; codes are upper-cased before lookup); an undeclared country is sent as `null` (`SquarePaymentMethod.CreatePaymentRequestAsync` → `createAddressAsync`).
- **A4 (scope):** DUPLICATE CLAIMS and UNKNOWN OUTCOMES settlement do not exist in the current code, and adding them is new behaviour beyond a minimal upgrade. The rows record the 3.0.0 operations and references available for them. **Decided:** not in upgrade scope; existing behaviour kept, and every row above records that.
- **A5 (scope, cross-operation invariants):** two invariants are not enforced today and need a new read: stored-card id ∈ `ListCards(customer)` before `CreatePayment`, and inventory location ids ∈ active locations before `BatchChangeInventory`. **Decided:** not added — they are new behaviour beyond a minimal upgrade and both were unenforced under 1.2.0; reported in the summary.
- **A6 (behaviour change: saved cards):** `Customer.cards` is gone, so saved cards now come from `GET /v2/cards?customer_id=…` (a different endpoint, paged at 25). Which OAuth scope `ListCards` needs is UNVERIFIED. The plugin already requests `PAYMENTS_READ` and `CUSTOMERS_READ`.
- **A7 (UNVERIFIED wire risk):** `Error.code` and `Error.category` are now `required`. A Square error entry missing either one makes `ReadErrorDetails` fall back to the exception message (non-2xx). The same gap in a 2xx `errors[]` raises `ResponseDeserializationException`, which `RefusalOrThrowAsync` reports as a Square failure.
- No blockers.
