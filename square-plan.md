# square-plan.md — ApimaticBench.Square 1.2.0 → 3.0.0 (Nop.Plugin.Payments.Square)

Upgrade only: the call surface (controllers, request records, routes, Case B errors) is unchanged in 3.0.0. What changed is the **model layer**. Many string fields are now open string-enums, `Customer.cards` is gone, three `CatalogItem` availability members are gone, the sandbox environment member was renamed, and several response members are now `required`. The 1.2.0 source is not available. Every "1.2.0-era" statement below is taken from how the existing code uses the API, and every 3.0.0 statement comes from the 3.0.0 map or the source file it names.

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Each operation that takes input takes ONE request record as its first parameter. Build it with an object initializer using the record's own property names, never flat arguments. `ListLocations` takes no record.
> ⚠ **Every SDK type is written fully qualified, with the namespace its source path implies** and taken from the path the map gives for THAT type: `src/Square/Models/X.cs` → `Square.Models.X`; `src/Square/Models/Enums/X.cs` → `Square.Models.Enums.X`; `src/Square/Requests/<Ctl>/X.cs` → `Square.Requests.<Ctl>.X`; `src/Square/Servers/` → `Square.Servers`; `src/Square/Core/Exceptions/` → `Square.Core.Exceptions`; `src/Square/Core/ErrorResponse/RawError.cs` → `Square.Core.ErrorResponse`. Inside `namespace Nop.Plugin.Payments.Square.*`, a bare `Square.` binds to the plugin namespace, so write `global::Square…` or add top-of-file usings/aliases.

### 2.2 Error model (every operation is **Case B**)

`Square.Core.Exceptions.ApiException<Square.Core.ErrorResponse.RawError>`:
- `.Error.StatusCode: HttpStatusCode` · `ReadAsBytes()` · `ReadAsString()` · `ReadAsJson<T>()`. `ReadAsJson<T>` = `JsonSerializer.Deserialize<T>(content)` with default options.
- The base `Square.Core.Exceptions.ApiException` carries `StatusCode`, `Headers` and `ContentType`.
- `ResponseDeserializationException : ApiException` (`TargetType`), `SdkConnectionException`, `SdkTimeoutException` and `AuthSchemeException` all derive from `SdkException`.
- No `…Result` (non-throwing) variants exist. No typed (Case A) errors exist.

The code's ladder (`RefusalOrThrowAsync`, the `IsNotFound` filters, `ReadErrorDetails`) matches 3.0.0 unchanged except D3. Source: `sdk-map.md` Error-handling model; `src/Square/Core/Exceptions/*.cs`; `src/Square/Core/ErrorResponse/RawError.cs`.

`Square.Models.Error` (wire): `Category (category): Square.Models.Enums.ErrorCategory, required` · `Code (code): Square.Models.Enums.ErrorCode, required` · `Detail (detail): string?` · `Field (field): string?`. **D3**: the code switches `error.Code` against string literals. That does not compile on a record type. Source: `src/Square/Models/Error.cs`.

### 2.4 Enum tables (all `OpenStringEnum` except `ServerEnvironment`)

Construction rule: static members only. There is **no public constructor or factory**. To turn a runtime string into a value, use `X.TryGetKnownValue(string?, out X?)`. It returns false for any value the SDK does not declare, and an unknown value cannot be built for sending. The `==` and `!=` operators against a `string` compile and compare `.Value`. There is an implicit conversion **to** `string`. **No** conversion runs **from** `string`. Record equality applies between two enum values. `ToString()` returns `.Value`. Source: `src/Square/Core/Enum/TypedEnum.cs`, `StringEnum.cs`, `StringEnumConverter.cs`. The converter reads a JSON `null` as a C# `null`, even on a `required` member.

## 6. Assumptions & Blockers

**Blockers:** none.

**Assumptions:**
- **A1 (major): D11, the catalog availability flags.** 3.0.0 `CatalogItem` has no `AvailableOnline`, `AvailableForPickup` or `AvailableElectronically`, and no replacement. Recommendation: keep sending them through `ItemData.AdditionalProperties` (snake_case wire names), as the code already does for `integration_id`, and update the test assertion to read the bag. The wire names and Square's continued acceptance are UNVERIFIED. The alternative is to drop them, which changes behaviour. Decided: the bag (`SquareCatalogService.BuildAvailability`); wire names confirmed against the 1.2.0 package.
- **A2: D5, saved cards.** `Customer.cards` is gone in 3.0.0. The plan reads saved cards with `Cards.ListCards { CustomerId }` and follows the cursor, which returns enabled cards by default. The alternative, reading `cards` from `Customer.AdditionalProperties` on RetrieveCustomer, keeps the old call but depends on a field the SDK dropped. ListCards is the plan.
- **A3 (major, scope):** The existing code has no DUPLICATE CLAIMS mechanism and reports a failure on ambiguous writes (UNKNOWN OUTCOMES). The task says this is an upgrade with minimal changes and that existing design is recorded, not reinvented. The plan therefore records what exists and the 3.0.0 operations that could settle each case, and left "Where in the code" open while planning. Decided: out of scope for the upgrade — rows marked "unchanged — out of upgrade scope"; the 3.0.0 call surface for settling them is unchanged from 1.2.0, so the upgrade neither adds nor removes a gap.
- **A4 (scope):** Two CROSS-OPERATION INVARIANTS are not enforced today: the stored-card id at checkout, and warehouse location ids for inventory. The invariant rules require adding those reads. Decided: not added — both are behaviour additions beyond the version upgrade and the 1.2.0 code did not enforce them either. Reported as pre-existing gaps.
- **A5:** D8 and D9. A store currency or country code that the SDK's `Currency`/`Country` enums do not declare cannot be sent in 3.0.0. Decided: currency → `NopException` "not supported by the Square" (`SquareEnumExtensions.ToSquareCurrency`); country → `null` (`SquareEnumExtensions.ToSquareCountry`), matching the old behaviour for an invalid region.
- **A6:** The 1.2.0 SDK source was not available. Every "1.2.0-era" fact is inferred from the existing code, and D16 ("newly required") may include members that 1.2.0 already required.
- **A7:** `Services/SquareAuthorizationHttpClient.cs` (OAuth obtain, renew and revoke) uses raw `HttpClient` and no `Square.*` type, so it is out of SDK scope. The SDK's `OAuth` controller is not adopted.
