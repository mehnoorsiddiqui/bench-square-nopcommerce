# square-plan.md — ApimaticBench.Square 1.2.0 → 3.0.0 upgrade (Nop.Plugin.Payments.Square)

Scope: an **upgrade**, not new integration work. Bump the package to exactly `3.0.0`, make every existing use match 3.0.0, keep the behaviour the same, and change tests only where they touch API that changed. All facts come from the 3.0.0 SDK map/source. The "1.2.0 usage" notes come from `git diff 1.2.0 3.0.0` of the same files in the reference clone.

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Every operation that takes input takes ONE request record as its first parameter, built with an object initializer whose property names are the record's own. Never pass flat arguments. `ListLocations` takes no record.
> ⚠ **Every SDK type is written fully qualified with the namespace its source path implies**, taken from the path for THAT type and never from a neighbour: `src/Square/Models/X.cs` → `Square.Models.X`; `src/Square/Models/Enums/X.cs` → `Square.Models.Enums.X`; `src/Square/Requests/<Ctl>/X.cs` → `Square.Requests.<Ctl>.X`; `ApiException<T>` → `Square.Core.Exceptions`; `RawError` → `Square.Core.ErrorResponse`; `ServerEnvironment` → `Square.Servers`; `AdditionalProperties` → `Square.Core.Models`. Inside `namespace Nop.Plugin.Payments.Square…`, a bare `Square.` resolves to the plugin namespace, so use `global::Square.…` or a top-of-file `using`.

Common to every row below:
- Error: **Case B**, `ApiException<RawError>`, accessors `StatusCode` · `ReadAsBytes()` · `ReadAsString()` · `ReadAsJson<T>()`.
- Throw-only.
- Server group `Default`.
- Auth `options.BearerAuth`.
- Every response envelope has `Errors: IReadOnlyList<Square.Models.Error>?` (`errors`).
- Routes are unchanged from 1.2.0: the non-doc diff of `Api/*.cs` for these ops is empty.

Source shorthand: `map/operations/<Ctl>.md` + the Type-sources file.

### Enum value tables (only those the code uses; all `OpenStringEnum` in `Square.Models.Enums`)

Mechanics for every enum below (`src/Square/Core/Enum/TypedEnum.cs`):
- `.Value: string`.
- Implicit conversion **enum → string**. There is no string → enum conversion and no public ctor/factory; use `TryGetKnownValue(string?, out T?)`.
- `==`/`!=` against `string` are declared and null-safe.
- Records compare by value.
- A `switch`/`is` with string constant patterns does not compile against the enum type.

## 3. Trap notes

- **Step 3/6/7/8/10, open enums vs strings.** A string-literal `switch`/`is` pattern fails to compile. `IReadOnlyList<Enum>.Contains("…")` fails to resolve. `Assert.That(enumValue, Is.EqualTo("…"))` compiles and then fails at runtime. Know how this SDK's enums compare, convert and match before touching each site. **MUST load `bench-square:dotnet-models`**
- **T3, step 5/10, implicit enum→string on a nullable.** Passing `x?.Currency` (or `CardBrand`, `State`) where a `string` is expected compiles through a user-defined conversion. What that conversion does with a null instance can crash code that never crashed on 1.2.0. **MUST load `bench-square:dotnet-models`**
- **Step 5, building an enum from a store value** (currency code, ISO country). There is no constructor. What happens when the store holds a code the SDK does not know decides whether a payment, refund or catalog sync is refused before it is sent. **MUST load `bench-square:dotnet-models`**
- **Step 5, name clash.** `SquarePaymentMethod.cs` already imports `Nop.Core.Domain.Directory` and `Nop.Core.Domain.Common`, which have their own `Currency`, `Country` and `Address`. A plain `using Square.Models.Enums;` there makes `Currency` and `Country` ambiguous (CS0104), as `Address` already is. That is why the file aliases `SquareModel`. **MUST load `bench-square:dotnet-models`**
- **Step 6, `ListCards` returns one page.** The 25-card page and the cursor contract decide whether ownership checks and the saved-card list see every card. **MUST load `bench-square:dotnet-configuration-resilience`** (pagination) and **`bench-square:dotnet-calling-endpoints`** (the request record with a non-nullable `IncludeDisabled`)
- **Step 7, a removed wire field.** Whether to drop it or carry it in the extension-data bag changes what Square receives (§6 A1). **MUST load `bench-square:dotnet-models`**
- **Step 2, environment rename.** A wrong environment member sends sandbox traffic to production. **MUST load `bench-square:dotnet-client-initialization`**
- **Step 4/11, error boundary.** `RefusalOrThrowAsync` classifies by exception type and status. Re-check that the enum-typed `Error` model does not change which exception surfaces for a bad error body. **MUST load `bench-square:dotnet-error-handling`**
- **Step 12, stubbing.** The stub serializes SDK models and keys on path. Enum and wire changes alter what it emits and what `RequestBody<T>` reads back. **MUST load `bench-square:dotnet-testing`**

**Hazard (verbatim):** a body that does not match its declared type surfaces as `ResponseDeserializationException`, an `ApiException` that keeps the HTTP status and names the target type but is **not** an `ApiException<TError>`. That covers two cases: a drifted or malformed **2xx** response (a missing `required` member), and a **non-2xx** body that does not match its operation's generated `{Operation}Error` shape. A catch ladder that handles only `ApiException<TError>` lets it escape, so it must also catch `ResponseDeserializationException` (or `ApiException`).

## 6. Assumptions & Blockers

- **A1 (major, needs user confirmation): catalog availability flags.** 3.0.0 `CatalogItem` no longer declares `available_online`, `available_for_pickup` or `available_electronically`, and nothing replaces them (`channels` is read-only). Option (a), recommended: stop setting them, which matches the 3.0.0 contract. Then change the `UpsertProduct_PublishesTheItemOnline` assertion on `ItemData.AvailableOnline` to assert the request's fields that still exist (`ProductType`, `PricingType`, ids). This is a change of the wire behaviour: Square no longer receives those flags. Option (b): keep sending them through `CatalogItem.AdditionalProperties` (the codebase already does this for `integration_id`). That keeps the wire behaviour, but it sends fields the 3.0.0 API does not declare, which goes against "every use must match the 3.0.0 API". Decided **(a)**: the three flags are no longer set in `SquareCatalogService.UpsertProductAsync` (`CatalogProductInfo.Published`/`IsDownload` are kept but unused); the test now asserts `Type`, `ProductType`, `PricingType` and price currency. Reported to the user as a behaviour change 3.0.0 does not let the code keep.
- **A2 (minor): saved cards source.** `Customer.cards` is removed in 3.0.0, so saved cards are read with `Cards.ListCards { CustomerId, IncludeDisabled = false }`, walking the cursor. The existing `Enabled != false` filter is kept. Behaviour is the same: the enabled cards of that customer.
- **A3 (minor): string → enum for store values.** Currency: `CheckSupportCurrency` already accepts only ISO 4217 codes. Map with `Currency.TryGetKnownValue(code.ToUpperInvariant(), …)`. When it is not found, throw `NopException($"The {code} currency is not supported by the Square")`; the wording follows the existing message. Before, the raw string was sent and Square rejected it. Apply the same to the catalog price and the legacy refund currency. For the legacy refund, the caller (`SquarePaymentMethod.RefundAsync`) already turns `NopException` into a refund error. Country: `TryGetKnownValue`, else `null`. Decided: `ToUpperInvariant` then `TryGetKnownValue`; an unknown currency throws `NopException` before the call, an unknown country is sent as `null` — implemented in `Services/SquareCodes.cs` (`SquareCodes.ToCurrency` / `SquareCodes.ToCountry`), used by `SquarePaymentMethod.CreatePaymentRequestAsync`/`RefundAsync`, `SquareCatalogService.UpsertProductAsync`, `LegacyTransactionService.RefundAsync`.
- **A4 (pre-existing gaps, out of upgrade scope, report only).** None of these is introduced by the upgrade, and fixing any of them would change behaviour, which the request forbids. Surface them to the user and do not implement them in this task.
  - The writes have no duplicate claim store.
  - There is no reconciliation of an ambiguous `CreatePayment`/`RefundPayment` after a connection failure (`RefusalOrThrowAsync` throws `SquareServiceException`).
  - A stored-card `SourceId` is not checked against `ListCards`.
  - There is no startup fail-fast for an empty production token.
- **No blockers.** Every operation the code uses exists in 3.0.0 with an unchanged signature, request record, route and error case (B).
