# square-plan.md — ApimaticBench.Square 1.2.0 → 3.0.0 upgrade (Nop.Plugin.Payments.Square)

Scope: every Square SDK use the plugin and its tests already make. No new features. All contracts below are from the 3.0.0 SDK map (`sdk-map.md`, `map/operations/*.md`) and the source files those pages name. 1.2.0 source was not available. A "MISMATCH" means the existing code does not match 3.0.0. It does not mean the mismatch is new in 3.0.0.

Paths in this file: code paths are relative to `src/Plugins/Nop.Plugin.Payments.Square/` (plugin) or `src/Tests/Nop.Plugin.Payments.Square.Tests/` (tests). SDK paths are relative to the SDK root.

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** An operation that takes input takes ONE request record as its first parameter. Build that record with an object initializer that uses the record's own property names, never flat arguments. An operation with no inputs (`ListLocations`) takes none. Every operation also takes `(…, Square.Core.RequestOptions? requestOptions = null, CancellationToken cancellationToken = default)`.
> ⚠ **Every SDK type is written fully qualified, with the namespace its source path implies.** Take that path from the map entry for THAT type, never from where a neighbouring type sits. `src/Square/Models/X.cs` → `Square.Models`, `src/Square/Models/Enums/X.cs` → `Square.Models.Enums`, `src/Square/Requests/<Ctl>/X.cs` → `Square.Requests.<Ctl>`, `Core/Exceptions` → `Square.Core.Exceptions`, `Core/ErrorResponse` → `Square.Core.ErrorResponse`, `Core/Models` → `Square.Core.Models`, `Core/Configuration` → `Square.Core.Configuration`, `Core/Hooks` → `Square.Core.Hooks`, `Servers` → `Square.Servers`.

**Error case, all rows:** every operation in scope is **Case B**: `Square.Core.Exceptions.ApiException<Square.Core.ErrorResponse.RawError>`. The accessors are `StatusCode: HttpStatusCode`, `ReadAsBytes()`, `ReadAsString()` and `ReadAsJson<T>()`. The SDK has no no-throw variant. Hierarchy (`src/Square/Core/Exceptions/*.cs`): `SdkException` ← `ApiException` ← `ApiException<TError>`; `ApiException` ← `ResponseDeserializationException` (`TargetType`); `SdkException` ← `SdkConnectionException` ← `SdkTimeoutException`; `SdkException` ← `AuthSchemeException`. The existing `RefusalOrThrowAsync`/`CatchExceptionAsync` ladder matches this hierarchy. **Auth, all rows:** `options.BearerAuth`. **Server group, all rows:** `Default`.

## 3. Trap notes (by step)

- **Step 2 (client).** The plugin builds a `SquareClient` per call from an `IHttpClientFactory` client. Who owns and disposes that `HttpClient`, and whether per-call construction re-reads env credentials each time, has costs that the signature does not show. **MUST load `bench-square:dotnet-client-initialization`.**
- **Step 2 (auth).** For a production store `AccessToken` can be null or blank. A null option silently falls back to an environment variable, and what a blank value does at call time is not visible from the options class. **MUST load `bench-square:dotnet-authentication`.**
- **Step 2 (resilience).** `HttpClient.Timeout` and `RetryOptions.Timeout` are both set to 30 s. What each one bounds, and so the real time a caller waits, cannot be read off the option names. **MUST load `bench-square:dotnet-configuration-resilience`.**
- **Steps 3–10 (calls).** Each call takes one request record whose required members the compiler enforces. Optional members carry defaults (`IncludeDisabled`, `WithDefinition`) that change what the server returns. **MUST load `bench-square:dotnet-calling-endpoints`.**
- **Steps 3–10 (enums).** Fields typed as open string enums compile against string literals in some positions (`==`) and not in others (`switch` patterns, collection expressions, `Contains`, assignment). The implicit conversion to `string` throws on null. An unknown value cannot be built for sending. Each of these costs either a build break or a runtime NRE or 400. **MUST load `bench-square:dotnet-models`.**
- **Step 5/8 (Currency/Country).** Store ISO codes must be resolved to `Currency`/`Country` members by exact wire value. What to do with a code the SDK does not declare changes what is sent. **MUST load `bench-square:dotnet-models`.**
- **Step 5/8/9/12 (validation attributes).** Request models carry `[StringLength]`/`[MaxLength]`/`[RegularExpression]`, for example the catalog idempotency key ≤128, the payment key ≤45, the attribute key regex. Whether these are enforced on the client or only by Square, and what is thrown, is not visible here. The catalog key is built from the store name and SKU, which have no length limit. **MUST load `bench-square:dotnet-models`.**
- **Step 6 (ListCards paging).** `ListCards` returns at most 25 cards per call and has no SDK pager. A single call silently drops cards for customers with more. **MUST load `bench-square:dotnet-configuration-resilience`.**
- **Step 5/6/7/10 (errors).** `CatchExceptionAsync` reads error bodies with `RawError.ReadAsJson<SquareErrorBody>()`. `Error.Category`/`Code` are now `required`, which changes what a partial error body does on deserialization. The refusal/failure split in `RefusalOrThrowAsync` relies on the exception family. **MUST load `bench-square:dotnet-error-handling`.**
- **Step 12 (tests).** Test models now need their `required` members. NUnit `Is.EqualTo("ADJUSTMENT")` against an enum-typed field compiles but **fails at runtime** (record vs string `Equals`). The stub route for saved cards moves. **MUST load `bench-square:dotnet-testing`.**

## 5. Assumptions & Blockers

**Blockers**

- **B1. Catalog availability flags removed (behaviour change).** `Square.Models.CatalogItem` in 3.0.0 has no `AvailableOnline`, `AvailableForPickup` or `AvailableElectronically` (`src/Square/Models/CatalogItem.cs`). `SquareCatalogService.UpsertProductAsync` sets all three from `Published`/`IsDownload`, and `SquareCatalogServiceTests` asserts `AvailableOnline`. The typed model cannot keep this behaviour. The closest 3.0.0 field, `Channels (channels)`, takes channel IDs such as a Square Online site ID, which the plugin does not have, so it is not equivalent. Sending the old fields through `AdditionalProperties` would need wire names the 3.0.0 map does not document. Done: dropped the three setters (`SquareCatalogService.UpsertProductAsync`) and the `AvailableOnline` test assertion. Reported to the user as a behaviour change.
- **B2. No duplicate-claim store.** There is nowhere to keep a claim that a store refuses on a second insert (see DUPLICATE CLAIMS). Adding one (a plugin table with a primary key, plus a migration) is outside a minimal dependency upgrade. This gap existed before 3.0.0. Planned default: no change, reported to the user.

**Assumptions**

- **A1. Saved cards now come from `Cards.ListCards`.** `Customer.Cards` is gone. `GetSavedCardsAsync` calls `ListCards { CustomerId = squareCustomerId }` and pages through `Cursor`. It keeps `IncludeDisabled = false` (the default, enabled only) and the `Enabled != false` filter. Behaviour is the same. Difference: an unknown Square customer used to produce a `RetrieveCustomer` 404, and `ListCards` probably returns an empty list instead (**UNVERIFIED**). Callers already treat both as "no cards" (the view component catches, and the SavedCards page shows its error resource). Test stub: `GET /v2/cards` returning `ListCardsResponse { Cards = … }`.
- **A2. Unknown currency or country codes.** No public factory exists, so a code the SDK does not declare cannot be sent. Currency (payment, refund, catalog, legacy refund): if `Currency.TryGetKnownValue(code, …)` fails, throw `NopException` "currency is not supported by Square".
