## 2. CONTRACT SHEET

> ⚠ Signatures are generated code, verbatim. Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs — `ListLocations` — takes none), built with an object initializer whose property names are the record's own, never flat arguments.
> ⚠ Every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits: `src/Square/Models/` → `Square.Models`, `src/Square/Models/Enums/` → `Square.Models.Enums` (**new `using` needed everywhere an enum static is named**), `src/Square/Requests/<Controller>/` → `Square.Requests.<Controller>`, `RawError` → `Square.Core.ErrorResponse`, `ApiException<T>`/`ResponseDeserializationException` → `Square.Core.Exceptions`, `ServerEnvironment` → `Square.Servers`, `RetryOptions`/`LoggingOptions` → `Square.Core.Configuration`, `SdkHook` → `Square.Core.Hooks`, `AdditionalProperties` → `Square.Core.Models`.

Every operation below: **Auth** `options.BearerAuth`; **Error** `Square.Core.Exceptions.ApiException<Square.Core.ErrorResponse.RawError>` — **Case B** (accessors `StatusCode`, `ReadAsBytes()`, `ReadAsString()`, `ReadAsJson<T>()`; 0 of 305 operations are Case A, so there is no typed `{Operation}Error` and no `TryGet…` accessor anywhere); throw-only; server group `Default`; signature tail `(…, RequestOptions? requestOptions = null, CancellationToken cancellationToken = default)` returning `Task<Response>`. Every response record carries `Errors: IReadOnlyList<Square.Models.Error>? (errors)`.

**Error model (`Square.Models.Error`)** — `Category (category): Square.Models.Enums.ErrorCategory, required`; `Code (code): Square.Models.Enums.ErrorCode, required`; `Detail (detail): string?`; `Field (field): string?`. 1.2.0-era code: `DescribeError` does `error.Code switch { "CARD_DECLINED" or … }` — **no longer compiles**; the test builds `new Error { Category = "PAYMENT_METHOD_ERROR", Code = "CARD_DECLINED" }` — **no longer compiles** (use statics). `RawError.ReadAsJson<T>()` is plain `JsonSerializer.Deserialize<T>(bytes)` with default options, so an error body whose `errors[]` item lacks `category` or `code` now fails the `required` check and throws `JsonException` (already caught in `ReadErrorDetails` → falls back to the exception message). Source: `src/Square/Models/Error.cs`, `src/Square/Core/ErrorResponse/RawError.cs`.

**Open-enum mechanics (all enums above are `OpenStringEnum<T>`, `src/Square/Core/Enum/TypedEnum.cs`)** — implicit `T → string` only (throws on null); `==`/`!=` against `string` (null-safe: `null == "x"` is false); `.Value`; `Is(string)`; static `TryGetKnownValue(string?, out T?)` (exact, case-sensitive; unknown → false); no public constructor, so an unknown value can be read but never built. A constant-pattern `switch`/`is` with string literals on an enum-typed value does not compile. NUnit `Is.EqualTo("…")` on an enum-typed value compiles but compares a record with a string (the record implements only `IEquatable<itself>`).

## 6. Assumptions & Blockers

- **B1 — DECIDED: flags removed** from `SquareCatalogService.UpsertProductAsync`; test asserts `ItemData.Name` instead; reported to the user. Original note — catalog availability flags: `Square.Models.CatalogItem` in 3.0.0 has no `AvailableOnline` (`available_online`), `AvailableForPickup` (`available_for_pickup`) or `AvailableElectronically` (`available_electronically`) member (`src/Square/Models/CatalogItem.cs`). `SquareCatalogService.UpsertProductAsync` sets all three and `SquareCatalogServiceTests.UpsertProduct_PublishesTheItemOnline` asserts `AvailableOnline`. Matching the 3.0.0 API means removing them: Square no longer receives "published online / pickup / downloadable" from nopCommerce. Recommended: remove the three assignments, change the test to assert what is still sent, and report the loss to the user. Pushing the old wire names through `AdditionalProperties` would send fields the 3.0.0 API does not declare — not recommended; needs the user's say-so if wanted.
- **B2 — Blocker (scope): duplicate claims and unknown-outcome reconciliation.** The 1.2.0-era code takes no pre-call claim and settles no ambiguous write; the task says "keep changes minimal and behaviour the same". The DUPLICATE CLAIMS / UNKNOWN OUTCOMES rows above therefore record "none — out of upgrade scope" and keep `TBD`. Recommended: leave as is for this upgrade and report it as a pre-existing gap; if the user wants it, it is a separate change.
- **A1 — Assumption (behaviour change): saved cards now come from `Cards.ListCards`.** `Customer.Cards` is gone in 3.0.0. `ListCards` with `CustomerId` returns only enabled cards by default (`IncludeDisabled = false`) and at most 25 per page, so the read walks `Cursor`. The visible result (enabled cards, mapped brand/type) stays the same; it now costs one or more `GET /v2/cards` calls instead of one `GET /v2/customers/{id}`. A Square 404 for an unknown customer no longer applies (ListCards just returns no cards).
- **A2 — Assumption (behaviour change): codes Square's enums do not declare.** `Money.Currency` and `Address.Country` can only be set to values the 3.0.0 `Currency` / `Country` enums declare (exact, case-sensitive). Plan: `Currency.TryGetKnownValue(code.ToUpperInvariant(), …)`; when unknown, throw the same `NopException("The {code} currency is not supported by the Square")` the code already throws from `CheckSupportCurrency`; for `Country`, an unknown code leaves `Country` null (today the code already sends null when the code is not a valid region).
- **A3 — DECIDED: not implemented** (keeps 1.2.0-era behaviour; reported as a pre-existing gap). Original note — stored-card ownership check before `CreatePayment`: Today a stored card id is sent if the Square customer merely exists. The plan adds the `ListCards` membership check (reusing `SquareCardService.GetSavedCardsAsync`) and refuses with `NopException` otherwise. If the user rejects any behaviour change here, drop this row and report it as an open gap.
- **A4 — Existing gap reported, not changed:** a blank production access token is not refused by `SquareClientFactory`; with 3.0.0 the SDK then uses `SQUARE_BEARER_AUTH` if set, else throws `AuthSchemeException` on the call, which reaches each caller the way any other call failure does today.
- **A5 — Test fixtures.** `SquareCardServiceTests` must stub `GET /v2/cards` with a `ListCardsResponse`; fixtures use enum statics (`CardBrand.Visa`, `TenderType.Card`, `RefundStatus.Approved`, `ErrorCategory.PaymentMethodError`, `ErrorCode.CardDeclined`, `Currency.Usd`); enum assertions compare `.Value` (or the static). The stub serializes SDK models with default `JsonSerializer` — fine, enum converters are attribute-based.
- **A6 — Retry defaults.** 3.0.0's `RetryOptions.Default()` (listed in §2.3) is what the factory now inherits apart from `Timeout`; 1.2.0's defaults are not in the repo, so any difference cannot be shown — the report should state the 3.0.0 values.
- **A7 — DECIDED: not implemented** (single read kept, see PAGED READS). Original note — inventory count cursor: `GetInStockQuantityAsync` reads one page today. Per PAGED READS it follows `BatchRetrieveInventoryCountsResponse.Cursor` (setting `BatchRetrieveInventoryCountsRequest.Cursor`) until empty; for the normal single-count answer this is the same one call and the same result.
