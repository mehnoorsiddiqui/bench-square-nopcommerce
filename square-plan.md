## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs — `ListLocations` — takes none), built with an object initializer whose property names are the record's own, never flat arguments. All have trailing `RequestOptions? requestOptions = null, CancellationToken cancellationToken = default`.
> ⚠ **Every SDK type is written fully-qualified with the namespace its source path implies**, taken from the path given for THAT type: `src/Square/Models/X.cs` → `Square.Models.X`; `src/Square/Models/Enums/X.cs` → `Square.Models.Enums.X`; `src/Square/Requests/<Ctl>/X.cs` → `Square.Requests.<Ctl>.X`; `src/Square/Core/Exceptions/` → `Square.Core.Exceptions`; `src/Square/Core/ErrorResponse/` → `Square.Core.ErrorResponse`; `src/Square/Core/Models/AdditionalProperties.cs` → `Square.Core.Models`; `src/Square/Servers/` → `Square.Servers`; `src/Square/Core/Configuration/` → `Square.Core.Configuration`; `src/Square/Core/Hooks/` → `Square.Core.Hooks`. **Enums now live in `Square.Models.Enums` — every file touching an enum needs `using Square.Models.Enums;`.**

Global facts (sdk-map.md): every operation is **Case B** — throws `Square.Core.Exceptions.ApiException<Square.Core.ErrorResponse.RawError>` (accessors `StatusCode` · `ReadAsBytes()` · `ReadAsString()` · `ReadAsJson<T>()`); throw-only, no `…Result` variants; no `Pageable` on any in-scope op; server group `Default`; **Auth** `options.BearerAuth` on every in-scope op.

### 2b. CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |

## 6. Assumptions & Blockers

- **B1 (behaviour change to flag to the user) — `CatalogItem.AvailableOnline / AvailableForPickup / AvailableElectronically` were removed in 3.0.0** (src/Square/Models/CatalogItem.cs has no such members and no boolean successor). Options: (a) keep sending them as `available_online` / `available_for_pickup` / `available_electronically` through `CatalogItem.AdditionalProperties` (wire-identical to today; whether Square still honours them is not knowable from the SDK — `UNVERIFIED`); (b) drop them (items no longer flagged online/pickup/electronic by this plugin). **Decided: (b)** — the flags are dropped in `SquareCatalogService.UpsertProductAsync`; sending fields 3.0.0 does not declare would be a guess about the live API. Reported to the user as a behaviour change the code cannot keep.
- **A1 — `Customer.Cards` removed** (D9): saved cards are read with `Cards.ListCards` filtered by `CustomerId`; enabled-only matches the old `Enabled != false` filter. One extra behavioural nuance: ListCards returns cards the account owns for that customer — equivalent intent. Flag in report.
- **A2 — empty/null access token in production** (D2): 3.0.0 falls back to the `SQUARE_BEARER_AUTH` environment variable when `BearerAuth` is null. **Decided: no change** in `SquareClientFactory.CreateAsync` — the 1.2.0 tag's `Core/` and `AuthSchemes.cs` are identical to 3.0.0's, so this fallback already existed and is not an upgrade change.
- **A3 — currency/country now closed to the SDK's known lists** (D3/D4): an ISO code that `Currency`/`Country` does not declare cannot be sent. Currency → `NopException` "not supported by the Square" (`SquareCodes.ToCurrency`); country → `null` (`SquareCodes.ToCountry`). Codes are upper-cased before lookup. Flag in report.
- **A4 — no new duplicate-claim / unknown-outcome machinery**: the task is a minimal upgrade with unchanged behaviour; the tables record `none added` deliberately. Not a blocker for this task.
- **A5 — stored-card ownership** before `CreatePayment` is not checked today (only the customer's existence); left unchanged.
- **A6 — tests**: T1–T5 change only where they construct/read changed SDK types; no test removed or skipped. The T1 stub answers `GET /v2/cards` (ListCards route, `src/Square/Api/Cards.cs`; `customer_id` travels in the query, which `StubSquare` ignores since it keys on `AbsolutePath`).
- No blockers that stop implementation.
