# square-plan.md — ApimaticBench.Square 1.2.0 → 3.0.0 upgrade (Nop.Plugin.Payments.Square)

Scope = the SDK surface the plugin and its tests **already use**. Every 3.0.0 fact below comes from the 3.0.0 SDK map (`sdk-map.md`, `map/operations/*.md`) or the source file the map names; paths are relative to the SDK root. The 1.2.0 surface was not available to read (no release notes, no cached 1.2.0 package), so the "existing code" column records what the code *does*, and the "3.0.0 delta" column records where that use does not match the 3.0.0 contract. The compiler is the backstop for anything the delta column misses.

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs — `ListLocations` — takes none), built with an object initializer whose property names are the record's own, never flat arguments. All return `Task<TResponse>`; trailing params are `RequestOptions? requestOptions = null, CancellationToken cancellationToken = default`.
>
> ⚠ **Every SDK type is written fully-qualified with the namespace its source path implies**, taken from the path the map gives for THAT type, never from where a neighbouring type sits: `src/Square/Models/X.cs` → `Square.Models.X`; `src/Square/Models/Enums/X.cs` → `Square.Models.Enums.X` (a *separate* namespace — `using Square.Models;` does not import it); `src/Square/Requests/<Controller>/X.cs` → `Square.Requests.<Controller>.X`; `src/Square/Core/Exceptions/` → `Square.Core.Exceptions`; `src/Square/Core/ErrorResponse/` → `Square.Core.ErrorResponse`; `src/Square/Core/Models/AdditionalProperties.cs` → `Square.Core.Models`; `src/Square/Core/Configuration/` → `Square.Core.Configuration`; `src/Square/Core/Hooks/` → `Square.Core.Hooks`; `src/Square/Servers/` → `Square.Servers`. **Inside `namespace Nop.Plugin.Payments.Square.*` a written-out `Square.` resolves to the plugin's own namespace — prefix `global::` (the code already does this for `global::Square.SquareClient`).**

## 6. Assumptions & Blockers

**Blockers:** none. Every in-scope operation, request record and route exists in 3.0.0 with the same name, record type and required members; all deltas are model-member types/removals.

**Behaviour 3.0.0 cannot keep as-is (flag in the final report):**

- **A1 — Catalog availability flags.** `CatalogItem` no longer declares `available_online`, `available_for_pickup`, `available_electronically`; `UpsertProductAsync` sets all three. Options: (a) keep sending them under those wire names through `CatalogItem.AdditionalProperties` (same wire body as today; whether Square still honours them is `UNVERIFIED`), or (b) drop them (items stop being flagged). Decision: (b) — the three flags are no longer sent (`SquareCatalogService.UpsertProductAsync`); sending undeclared fields would be a guess that Square still honours them. Reported as lost behaviour; the catalog test now asserts the item type/name instead of `AvailableOnline`.
- **A2 — Saved cards source.** `Customer.cards` is gone; `SquareCardService.GetSavedCardsAsync` switches to `Cards.ListCards` with `CustomerId` set and the cursor walked. Cost: one extra GET per page (≤25 cards each); `RetrieveCustomer` is no longer needed in `GetSavedCardsAsync`. Disabled cards are excluded server-side by default (existing `Enabled != false` filter kept). `ListCards` with `CustomerId` unset would return the merchant's cards — the existing early return for an empty customer id must stay ahead of the call.
- **A3 — Currency / Country as enums.** No conversion from `string`; only known members can be built (`TryGetKnownValue`, exact upper-case match). Decision default: Currency not known to the SDK → throw `NopException` with the existing "currency is not supported by the Square" wording (the plugin already rejects non-ISO currencies); Country not known → leave `Address.Country` null (the code already nulls invalid ones). Decision: confirmed and implemented in `SquarePaymentMethod.GetSquareCurrency` / `CreatePaymentRequestAsync`, `SquareCatalogService.UpsertProductAsync`, `LegacyTransactionService.RefundAsync` (codes upper-cased before `TryGetKnownValue`, matching the case-insensitive `CheckSupportCurrency`).
- **A4 — Required members on response models.** `Refund` (Id, LocationId, TenderId, Reason, AmountMoney, Status), `Tender.Type`, `PaymentRefund.Id/AmountMoney`, `CatalogObject.Type/Id`, `Error.Category/Code` are `required`: a body missing one now fails the whole call with `ResponseDeserializationException` instead of yielding nulls. `UNVERIFIED` whether live bodies ever omit them; directive: every path that previously tolerated nulls must still end in the same user-visible outcome — in particular `SquarePaymentMethod.RefundAsync` legacy branch catches only `NopException`, so an SDK exception from `LegacyTransactionService` escapes it (pre-existing for `ApiException`; decision: not widened — unchanged from 1.2.0, reported).
- **A5 — `Location.Capabilities` / `Status`.** Comparisons must use enum members; behaviour unchanged when done right (a wrong comparison would silently mark every location unusable and break checkout).
- **A6 — Decline message mapping.** If any `errors[]` item lacks `code` or `category`, `ReadAsJson<SquareErrorBody>` now throws `JsonException` (caught) and the customer sees the SDK exception message instead of the friendly decline text. `UNVERIFIED`; acceptable degradation.

- A7 — "Change no other dependency": only the `ApimaticBench.Square` `Version` attribute changes; if restore reports a transitive conflict, record it rather than adding package references.
- A8 — Pre-existing invariant gaps in §2d (stored-card membership before `CreatePayment`, location membership on admin save, warehouse location ids for inventory) are not introduced by the upgrade. The user asked for minimal, behaviour-preserving changes; Decision: not added in the upgrade (behaviour-preserving scope); reported.
- A9 — DUPLICATE CLAIMS / UNKNOWN OUTCOMES redesigns (claim table, outcome settling) are recorded, not mandated: decision recorded in those rows: not implemented, 1.2.0 behaviour kept.
